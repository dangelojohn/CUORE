# Methods and gotchas

- Tests: plain scripts `cuore/tests/check_*.py`, `mes-log-mcp/tests/check_*.py`, `obd2-mcp/tests/check_*.py`; each sets CUORE_STATE_DIR to a temp dir before importing cuore and never writes to C:\ProgramData\cuore. Run them all once before a commit: `for t in ...; do .venv/Scripts/python.exe $t; done`.
- Headless Edge on this PC: `--dump-dom` and `--screenshot` do not work; drive Edge over the DevTools Protocol (pattern in `cuore/tests/check_live_widgets.py`) and kill it by its temp `--user-data-dir` with `cuore/tests/_edge_cleanup.py`, otherwise processes leak (266 found once).
- Verifying links: YouTube via oEmbed; forums and part sites block plain HTTP (202 bot wall or 403), so verify by opening the page in headless Edge and reading the title and first post, or the product image's natural size.
- Jinja: a dict key named `items` is shadowed by `dict.items()`; use bracket access or rename. Each `*_routes.py` module creates its own Jinja environment, so Jinja globals must be registered on each (see `experience_globals.py`, `timeline_routes.py`).
- Starlette uploads arrive as `starlette.datastructures.UploadFile`, not FastAPI's subclass; duck-type on `filename`/`read`.
- CUORE health endpoint: `/api/health`. The keep-alive identifies cuore by the health body. `cmd /c` needs extra outer quotes.
- Owner's manual (2018 US Stelvio, Mopar PDF) is a CONFIRMED source; decode the maintenance plan's bullet columns by character x-position.
- MES language files hold only description fragments; the code-to-text map is in MES's encrypted database (left alone).
- Git: agent-driven `git push` is blocked by the permission classifier; the owner approves a direct `git push github main`. Remote `forge` is unrelated; never push there.
- PDF sheets: reportlab in the project venv; render with pypdfium2 and look at the PNG; one US Letter page each; generators live in `docs/vehicles/<VIN>/pdf-sources/`.
- Serving "Tell CUORE" (`/m/{vin}`) to a phone on the shop LAN: the bind setting is `CUORE_HOST` (`cuore/config.py`, default `127.0.0.1`), not a separate `CUORE_BIND` -- one setting already does this, so a second was not added. Setting `CUORE_HOST=0.0.0.0` in the keep-alive makes the app reachable from every device on the LAN with **no authentication** unless `CUORE_TOKEN` is also set -- that is the owner's decision, not a default (see `Settings.lan_exposed`/`unguarded_lan`). `GET /m/{vin}/qr` only renders the LAN URL when `lan_exposed` is true; it prints the URL as selectable text (no `qrcode` package in this venv, and a from-scratch QR matrix generator was out of scope) rather than a QR image.
- "Read this photo" (`POST /api/vision/{vin}/read`, `cuore/services/vision_bridge.py` + `cuore/api/vision.py`): a value read from a photo is a **suggestion the human confirms**, never a car measurement -- when the confirmed value is saved as an owner event, the caller stamps `fields_meta[key] = "photo"` on that field (same provenance convention `cuore.live.owner_events` already uses) so the record still says it came from a picture, not an instrument. Field names in the response are the real `cuore.live.owner_events.TAXONOMY` field names for the hints that map onto one kind (`fuel_pump` -> `fuel/fill_up`, `oil_bottle` -> `fluids/engine_oil_change`, `part_label` -> `parts_repairs_elsewhere/part_fitted_elsewhere`, `receipt` -> `fuel/fill_up`); `odometer` returns `odometer_km` with `suggested_kind: null` because that is the event's own top-level field, not a kind field. Provider is `CUORE_VISION_PROVIDER` (default `none`, which is deliberately the honest "not set up, fill in by hand" answer -- CUORE runs offline by rule, so a vision backend is never silently on). `claude` only turns on with `CUORE_VISION_PROVIDER=claude` **and** `ANTHROPIC_API_KEY` set -- that call leaves the LAN and goes to Anthropic over plain HTTPS via `urllib` (no `anthropic` SDK in this venv, and none was added), so it is the owner's explicit, informed choice, never a default. `tesseract` is a probe-only stub (`_find_tesseract` checks PATH and `C:\Program Files\Tesseract-OCR\tesseract.exe`); nothing is installed there today and no OCR is wired up behind it. Tests (`cuore/tests/check_vision.py`) monkeypatch `cuore.services.vision_bridge.urllib.request.urlopen` to return a canned Messages-API body rather than calling the real network.

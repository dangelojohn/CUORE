Why this matters — F1 multi-channel telemetry principle
F1 engineers never look at single channels. They compute cross-correlations between channels to find hidden causal relationships invisible in any individual signal. A Ferrari 458 ground fault was identified not from a ground-voltage sensor (there isn't one) but from the phase relationship between battery voltage sag and CAN error counter rate — the sag led the error by 180ms consistently. That 180ms lag was the causal proof. To replicate this on your Stelvio, you need to log the right channels simultaneously. The X431 supports 12-channel simultaneous logging with CSV export. Cross-Correlation Matrix — F1 Telemetry Method
The Pearson correlation coefficient r between every pair of logged channels, computed over the full dataset. r > 0.7 = strong positive, r < -0.7 = strong inverse. The clinically significant finding is when a parameter that should not correlate with another shows r > 0.7 — that is the hidden causal relationship. In a healthy Stelvio, battery voltage and BSM error counter should have r ≈ 0. In a car with G102 degradation, they should correlate strongly. The first time you see that correlation, you have found the fault 3–6 months before a DTC fires.

Pre-Fault Detection — BITE-Inspired Continuous Health Monitoring
The F-35 ALIS system runs 10,000 parameter health checks per flight and flags parameters trending toward failure thresholds before they cross. This tab applies the same logic to your X431 data. For each monitored parameter, it computes a degradation trend (linear regression slope), a time-to-threshold projection, and a health score. Parameters currently within spec but degrading are flagged as pre-fault conditions — exactly the margin between "no DTC" and "active fault."

The X431 exports one row per sample. Sample rate is approximately 2–4 Hz depending on number of PIDs selected and CAN bus speed. For the 12-PID critical set, expect ~3 Hz. A 20-minute drive at 3 Hz = ~3,600 data rows per PID. This is sufficient for meaningful cross-correlation analysis.
Known X431 export quirks
QUIRK 1Time column may be missing or in ms not seconds. The import tool handles both formats.
QUIRK 2Some PIDs update at different rates — sparse columns normal. Tool interpolates linearly.
QUIRK 3Column headers may include units in brackets — e.g. "Battery_Voltage(V)". Tool strips these.
QUIRK 4.x431 binary files require the Launch PC software to export to CSV first. Cannot be dropped directly.
